# 텍스트가 화면에 뜨는 두 경로

이 게임의 화면 문자는 **두 개의 완전히 다른 경로**로 나온다. 섞어서 다루면
"UI 가 나중에 계속 문제가 되는" 전형적인 함정에 빠진다.

---

## 경로 A — 폰트 렌더 (본문 폰트 `0xF4001`)

| 항목 | 값 |
|---|---|
| 시트 | `0xF4001` ~ `0xF7001` (뱅크 `0x3D`) |
| 규격 | 8×8, GB 2bpp, **16 B/글리프**, lo 플레인 == hi 플레인 |
| 글리프 수 | 768 (`0x000`~`0x2FF`) |
| 압축 | **없음** (평문 타일) |
| 방식 | 텍스트 바이트 → 글리프 인덱스 → **ROM 에서 VRAM 타일로 즉시 복사** |

즉 대사는 미리 그려둔 그림이 아니라 **그때그때 VRAM 에 찍는다**. PoC 에서
글리프 슬롯을 한글 비트맵으로 덮자 VRAM 타일이 그 비트맵과 바이트 단위로
일치한 것이 증거다.

이 경로로 나오는 것:

- 이벤트 대사 전체
- **아이템·기술 이름과 설명** (레코드 테이블, `docs/03_ui_tables.md`)
- 시스템 메시지, 전투 대사
- 지명 배너 (「宇宙船内部」) — 팔레트만 다시 칠할 뿐 같은 폰트다
  (마스크는 hi 플레인, lo 플레인은 배경색 `0xFF` 로 채움)

---

## 경로 B — 베이크드 UI 그래픽 (`0xF7001` ~)

본문 폰트 **바로 뒤**에 붙어 있는 별개의 타일 시트다. 압축은 없고 같은 2bpp
8×8 이지만, **문자가 아니라 그림**이다 — 텍스트 인코딩으로 조립되지 않고
타일맵에 직접 배치된다. 따라서 판독표·포인터와 무관하고,
`references/strategy/graphics-text.md` 의 그래픽 교체 파이프라인으로 가야 한다.

확인된 내용물 (라벨 격자 `out/ui_sheet_*.png`):

| 타일 | 내용 |
|---|---|
| `0x000`~ | 커서·화살표·창 괘선 |
| — | **STAR OCEAN BLUE SPHERE 로고** |
| — | 숫자 세트 여러 벌 (`0-9`, `0-15`) |
| `0x060`~`0x09F` | 아이템·상태 아이콘 |
| `0x0A0`~`0x0A9` | 큰 숫자 `0`~`9` |
| `0x0AA`~`0x0AC` | **「フォル」** (화폐 단위) |
| `0x0BA`~`0x0BE` | **「MENU」** |
| — | **「HELP」** |
| — | **파티원 이름 라벨** (CRAWD / RENA / CELINE / OPERA / ASHTON / BOWMAN / DIAS / NOEL / PRECIS / LEON / ERNEST / CHISATO) |
| 뒤쪽 대부분 | 캐릭터 얼굴 초상 |

### 한글화 판단 — ✅ **전부 결정났다** (2026-08-17)

- **「フォル」** → ✅ **「폴」로 교체 완료** (wip95, `0x0F7AA1~`). `scripts/uigfx.py`.
- **「MENU」/「HELP」** → ⛔ **영문 그대로 둔다 (사용자 결정 2026-08-17).**
  한국인도 그대로 읽고, 상점 버튼 `BUY`/`SEL`/`FIN` 도 이미 영문으로 뒀다
  (FR/ES 완역판도 로마자로 풀었다). 칸이 좁아 「메뉴」·「도움말」이 안 들어간다.
- **파티원 이름 라벨** → ⛔ **영문 그대로 둔다** (같은 결정).
  칸 폭이 이름마다 다르고 (BOWMANDIAS 처럼 붙어 있는 곳도 있음) 얻을 것이 적다.
- 로고·아이콘·초상 → 손대지 않는다.

⇒ **경로 B 에 남은 일본어는 0 이다.** 여기 남은 로마자는 미번역이 아니라 **결정**이다.

---

## 함정

1. **두 경로를 같은 도구로 다루지 말 것.** 경로 A 는 판독표·포인터·글리프 예산
   문제이고, 경로 B 는 타일 그래픽·팔레트·배경 복원 문제다.
2. **경로 B 를 미번역으로 오인하지 말 것.** 폰트 슬롯을 아무리 뒤져도 「MENU」는
   안 나온다. 그래픽이기 때문이다.
3. 본문 폰트 시트 바로 뒤(`0xF7001`)에 UI 시트가 붙어 있어서 **본문 폰트를
   768글리프 너머로 확장하려면 UI 시트를 먼저 옮겨야 한다** (§ 아래).

## 글리프 예산 (경로 A)

`scripts/glyph_usage.py` 실측 — 텍스트가 실제로 참조하는 슬롯:

| 구분 | 개수 |
|---|---|
| 전체 슬롯 | 768 |
| 텍스트가 참조 | 678 |
| **미참조(즉시 가용)** | **90** |
| 출현 3회 이하(회수 후보) | 109 |

미참조 연속 구간: `0x000-0x00F`(16) · `0x109-0x10C`(4) · `0x135-0x13F`(11) ·
`0x206-0x20F`(10)

### ⛔ 정정 — "UI 시트만 옮기면 1024슬롯" 은 **틀렸다**

한때 `주소 = 0x4001 + idx × 16` 으로 계산할 거라 보고 "뱅크만 안 넘으면 1024개까지
공짜"라고 적었다. 실제 코드를 찾아 보니 아니다. 엔진은 **리드바이트별 베이스 주소를
하드코딩**한다 (`scripts/glyph_base_sites.py`):

```
11 01 40   LD DE,$4001     ; 리드 없음  -> page0 (글리프 0x000-0x0FF)
FE 5E      CP $5E
20 06      JR NZ,+6
2A         LD A,(HL+)
11 01 50   LD DE,$5001     ; 0x5E       -> page1 (0x100-0x1FF)
18 08      JR +8
FE 5F      CP $5F
20 04      JR NZ,+4
2A         LD A,(HL+)
11 01 60   LD DE,$6001     ; 0x5F       -> page2 (0x200-0x2FF)
```

최대 도달 주소는 `$6001 + 0xFF×16 = $6FF1`. **엔진은 코드 패치 없이 글리프 0x2FF를
넘을 수 없다.** UI 시트를 옮겨도 슬롯은 한 개도 안 늘어난다.

### 0x300 페이지를 추가하려면 — 손댈 곳 전수

✅ **완료.** 전수 목록·설계·함정은 `docs/06_engine_patch.md` 가 정본이다.
여기서는 **한때 이 문서가 틀리게 적었던 것**만 남겨 둔다(같은 길을 다시 파지 않도록).

⛔ **예전에 "손댈 10곳 + 스캐너 6곳 = 16곳"이라고 적었는데 둘 다 틀렸다.**

| 예전 목록 | 실제 |
|---|---|
| `0x0380CF` (베이스 사이트) | **아니다.** `$40B9` 의 **텍스트 포인터 뱅크 넘김 처리**다. 포인터가 `$8000` 을 넘으면 뱅크를 +1 하고 `HL=$4001` 로 되돌린다(`$4000` 이 아닌 이유는 뱅크 첫 바이트가 뱅크 ID라서). 고치면 포인터가 깨진다 |
| `0x02E4AB` `0x02E4E9` `0x02E523` (스캐너) | **아니다.** 전부 `LD A,($CFD0)` 뒤 — `$CFD0` 은 **장면/맵 인덱스** 전역변수다(ROM 전역 167회 읽기, 비교 상수 1~126). 진짜 스캐너와 달리 `CP $5F` 짝이 없다 |
| (빠져 있었음) | `0x03CF3C`(뱅크15) `0x2A1480`(뱅크168) — **진짜 스캐너 2곳**. 전수 감사로 뒤늦게 찾았다 |

**판별 기준: 진짜 리드 스캐너는 24바이트 안에 `CP $5E` 와 `CP $5F` 가 짝으로 있다.**
ROM 전체 `CP $5E` 93건 중 짝이 있는 것이 15건이고 그게 정확히 전체 사이트다.
짝 없는 78건은 전부 다른 상수 비교이거나 그래픽 데이터다.

최종: 베이스 9곳 + 스캐너 6곳 = **15곳** (+ 뱅크 즉치 8곳).
`scripts/audit_engine.py` 가 미패치 0건을 매 빌드마다 증명한다.

⚠ **스캐너를 빠뜨리면 글자가 안 깨지고 줄 폭만 틀어진다** — 다음 글자를 덧그리는
유령/겹침 증상으로 나타나서 원인 추적이 훨씬 어렵다.

### 인코딩 공간

패치 후 **1280슬롯**(5페이지). 리드바이트는 `$5E`→page1, `$5F`→page2,
`$5D`→page3, **`$5C`→page4** 이고, 패치된 코드는 범위비교라 `$5C~$5F` 넷
모두를 리드로 본다. 그래서 원본의 `$5C`=¥ `$5D`=』 는 포기한다.
규약 정본은 `scripts/krcodec.py`.

**page4 는 다른 뱅크(0xFB)에 있다.** 뱅크 창이 `$4000-$7FFF` = 정확히
4페이지라 5페이지째는 물리적으로 같은 뱅크에 못 들어간다. 엔진은 그 사실을
**베이스 상위바이트의 bit7** 로 운반한다(page4 = `$C0`). 복사 직전에
`h_fb_*` 헬퍼가 `BIT 7` 로 뱅크를 고르고 `RES 7` 로 주소를 되돌린다.
→ 뱅크를 실어 나를 레지스터도 RAM 도 필요 없다. `docs/06` §"다음 확장" 참조.

⚠ 시트는 `0x3E8001` 부터 **선형**이다 — `FONT_BASE + 0x400*16 = 0x3EC001`
   이 곧 뱅크 0xFB 의 `$4001` 이라 특수 처리가 없다. 대신 글리프 `0x3FF` 의
   마지막 바이트가 **뱅크 0xFB 의 ID 각인 자리**와 겹치므로 배정 금지다
   (`krcodec.BANK_ID_SLOTS`, `build_kr` 가 각인을 검사한다).

⛔ **글리프 슬롯 `0x5C~0x5F` 에 음절을 배정하면 안 된다.** 실제로 `0x5C` 에
「프」가 배정된 채 되읽기 검증 429/429 를 통과했다(인코더·디코더가 사이좋게
같은 규약을 몰랐기 때문이다). `docs/06_engine_patch.md` §"검증이 통과하는 버그".

## ⛔ 회수하면 안 되는 글리프 슬롯

`glyph_usage.py` 는 **텍스트가 참조하는 슬롯만** 센다. 코드가 글리프를 직접
쓰는 경우는 못 본다. 두 종류가 있고 **둘 다** 회수 금지다.

### (a) 코드가 값으로 인덱스를 **계산**하는 슬롯 — `alloc_glyphs.PINNED`

| 슬롯 | 근거 |
|---|---|
| `0x30`~`0x39` 숫자 | `0x038527 ADD A,$30 / CALL $489E` · `0x03A399 ADD A,$30 / CALL $63D4` |
| `0x20` 공백 | 폭 스캐너가 `CP $20` 으로 판정(`0x0249AB`). 스페인어·프랑스어 완역판도 이 슬롯만은 원본과 바이트 동일 |

⛔ 실제로 밟았다: 번역문에 3·4·6·7 이 안 나와서 그 슬롯이 "비었다"고 잡혔고
「로」「시」「어」「약」이 배정됐다. **HP·MP·소지금·데미지에 3/4/6/7 이 들어갈
때마다 한글이 나온다.** 빈도 통계로는 절대 안 보이는 종류다.

### (b) 코드가 주소를 박아 VRAM 으로 복사하는 구간 — `alloc_glyphs.CODE_USED`

`scripts/bankrefs.py` 로 뱅크 `0x3D` 참조를 전수 조사해 나온 것:

⛔ **2026-08-15 정정 — 옛 표는 페이지를 한 칸 올려 잡았다.**
`bankrefs.py` 가 뱉는 것은 **CPU 주소**이고, 페이지 p 의 베이스는 `$4001 + p*$1000`
이다. 그러니 `$4101` 은 page0 의 17번째 글리프 = **`0x010`** 이지 `0x110` 이 아니다.
이 착오로 `0x110-0x119`·`0x127`·`0x12F`·`0x138-0x13F` 등 **19슬롯을 헛되이 막고**
있었고, 글리프가 바닥나 번역문의 어휘를 깎던 원인이었다.

| 소스 주소 | 글리프 (정정) | 길이 | 비고 |
|---|---|---|---|
| `$4001` | `0x000`~`0x01F` | 최대 `0x200` | UI 괘선·커서 |
| `$4101` | `0x010`~`0x017` | `0x80` | ~~0x110~~ |
| `$4181` | `0x018`~`0x019` | `0x20` | ~~0x118~~ |
| `$4271` | `0x027` | `0x10` | ~~0x127~~ (「×」) |
| `$42F1` | `0x02F` | `0x10` | ~~0x12F~~ (「／」) |
| `$4301` | `0x030`~`0x039` | `0xA0` | ~~0x130~~ — **숫자 슬롯이다**(PINNED 와 같은 자리) |
| `$5141` | `0x114` | | page1 베이스가 `$5001` 이라 이건 진짜 page1 |
| `$5371` | `0x137` | `0x10` | 진짜 page1 |
| `$6501` | `0x250`~`0x25B` | `0xC0` | 진짜 page2 |

실측 전수(`python scripts/bankrefs.py <rom> 0x3D`, 56건)로 **코드가 VRAM 으로
퍼 가는 글리프는 58개**뿐이다:

    0x000-0x01F, 0x027, 0x02F-0x039, 0x114, 0x137, 0x250-0x25B

⚠ 회수 금지에는 종류가 하나 더 있다 — **우리 번역문이 원본 글리프를 그대로 쓰는**
슬롯(`alloc_glyphs.TEXT_RESERVED`). 지금은 `0x130`~`0x136` (fieldhelp 의 ↑ ↓ ← → ✛
구분선)뿐이고, `build_kr.TAKEN` 가드가 이 규약을 기계로 지킨다.

⚠ 옛 경고도 여전히 유효하다: 메인 메뉴가 `0x13C`~`0x13F` 로 「ステータス」를
그리고 있었고 거기 한글을 배정해 메뉴가 깨진 적이 있다. 지금은 메인 메뉴를
재패킹으로 한글화해서 그 참조가 사라졌다. **원본 글리프를 계속 쓰고 싶으면
반드시 `TEXT_RESERVED` 에 올릴 것.**

⚠ 이 구간들은 **폰트 이전 후에도 원본 뱅크 `0x3D` 에서 읽힌다**. 패치는 뱅크
`0x3D` 를 지우지 않고 `0xFA` 에 사본을 만들 뿐이고, 벌크 프리로드 55곳의
`LD A,$3D` 는 그대로 둔다. 위 슬롯들은 회수 금지라 내용이 같으므로 결과가
동일하다 — **의도된 것이다**(`audit_engine.py` 가 렌더 경로와 구분해 센다).

## ⚠ 뱅크 스와핑 전제

GB 계열은 뱅크를 수시로 갈아 끼운다. **ROM 이미지에서 비어 보이는 뱅크**(전부 `0x00`)는
데이터가 없다는 뜻이지, 그 논리 주소창이 항상 비어 있다는 뜻이 아니다.
새 데이터를 넣을 때는 **뱅크 번호로 소유권을 잡고**(빈 뱅크 통째로), 이미 쓰이는
뱅크의 남는 구간에 끼워 넣지 않는다. 후자는 다른 코드가 그 창에 다른 뱅크를
매핑한 순간 엉뚱한 걸 읽는다.

## 단계 계획

| 단계 | 내용 | 필요한 개조 |
|---|---|---|
| **1. UI 먼저** | 아이템·기술·시스템 메시지 한글화 | **코드 패치 없음** — 가나/한자 슬롯 회수분(≈630)으로 충분 |
| 2. 그래픽 UI | 「フォル」→「폴」 | 타일 교체 (경로 B) |
| 3. 대사 | 이벤트 스크립트 전량 | 필요 음절이 630을 넘으면 그때 4번째 페이지 추가(16곳 패치) |

**핵심은 엔진 패치를 마지막까지 미루는 것이다.** 1단계는 폰트 비트맵 교체 +
텍스트 재삽입만 하므로 코드를 한 줄도 안 건드린다. UI 가 확정된 뒤에
3단계의 위험한 개조를 하면, 깨진 게 생겼을 때 원인이 개조라는 걸 바로 안다.

3단계에서 실제 필요 음절 수를 세고 630 이하면 패치 자체가 필요 없다.
넘을 때만 16곳 패치로 간다 — **필요하다고 확인되기 전에는 하지 않는다.**
