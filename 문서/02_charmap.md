# 판독표 (charmap)

정본 데이터: `assets/charmap_kanji.json` (한자) + `scripts/charmap.py` (ASCII·가나, 코드 상수)

## 1. 확정 구간 — ASCII·가나

시트 렌더(`out/jp_font_sheet.png`) + 화면 VRAM 대조로 **확정**.

- `0x30`~`0x39` = `0`~`9`, `0x41`~`0x5A` = `A`~`Z`
- **히라가나 `0x60`~**, **가타카나 `0xB0`~** — 두 구간의 배열이 완전히 동일하다.
  5자 그룹 순서: `あ か が さ ざ た だ な は ば ぱ ま / やゆよ / らりるれろ / わをん / 소문자9자`
  즉 탁음·반탁음 행이 청음 행 바로 뒤에 끼어 있다. (`さ=0x6F`, `せ=0x72`, `の=0x87`, `ン=0xF6`)
- `0x5E`, `0x5F` 는 텍스트 스트림에서 **한자 리드 바이트**로 쓰인다.
- `0x10`~`0x1F` 도 **실제 글리프**다(제어코드가 아니다). `0x10`~`0x1A` UI 괘선, `0x1B` ✱,
  `0x1C`~`0x1F` 는 한자. 디코더가 `{1E}` 처럼 토큰으로 남기므로 판독 필요.

## 2. 한자 판독 방법 — 2중 교차검증

8×8 한자는 **비트맵만 보고 단정하면 오독한다**. 두 증거가 일치할 때만 등재한다.

1. **비트맵**: `scripts/glyph_grid.py` 로 인덱스 라벨과 함께 렌더해서 본다.
   라벨을 같이 그려야 위치를 세다 어긋나는 사고가 없다.
   ```
   python scripts/glyph_grid.py roms/<rom> 140 64 -o out/g_140.png --cols 8 --scale 10
   ```
2. **문맥**: `scripts/kanji_ctx.py` 가 코퍼스 전체에서 각 토큰의 빈도와 용례를 뽑는다.
   활용형이 결정적 증거다 — `{K:14D}う`/`{K:14D}われる` → `言`, `{K:110}り{K:164}した` → `作り出した`.
   ```
   python scripts/kanji_ctx.py roms/<rom> out/text_blocks.tsv -o out/kanji_ctx.txt
   ```

두 증거가 어긋나면 등재하지 않고 보류한다. 문맥이 서로 맞물려 연쇄 확정되는 경우가 많다 —
`{K:151}{K:14B}にも` + `{K:14B}が{K:164}{K:174}る` 로 `何事にも` / `事が出来る` 가 동시에 풀린다.
