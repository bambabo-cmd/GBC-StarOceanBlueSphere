# 실기 QA — 되는 방법과, 안 되는 줄 알았던 것들

## ⛔⭐⭐ 브레이크포인트 — 세 가지를 모르면 「코드가 안 돈다」로 오판한다 (2026-08-18)

`btcmd` 을 쫓다가 **두 번 오판했다.** 셋 다 증상이 「BP 가 조용하다」로 똑같다.

| | BP 가 걸리나 | 뱅크를 가리나 |
|---|---|---|
| `tap` / `step` — **정지 상태**로 프레임 밀기 | ❌ **평가 자체를 안 한다** | — |
| `resume` → `run_frames(n)` | ✅ (`status:"interrupted"` + `breakpoint_id` 로 돌아온다) | — |
| `gameboyMemory` + **CPU 주소** | ✅ | ❌ **안 가린다** |
| `gbPrgRom` + **ROM 오프셋** | ✅ | ✅ **가린다** |

1. **`tap` 으로는 BP 가 안 걸린다.** 프레임은 흐르는데 BP 만 조용하다.
   ⇒ BP 를 쓰는 조사는 **반드시 `resume` + `run_frames`** 로 한다.
2. **CPU 주소 BP 는 뱅크를 안 가린다.** `$4340` 에 걸었더니 뱅크 **6** 에서,
   `$7500` 에 걸었더니 뱅크 **212** 에서 걸렸다 — 찾던 뱅크 55 가 아니다.
   화면 그림 데이터가 우연히 그 주소에 있으면 그냥 걸린다.
   ⇒ **뱅크가 중요한 조사는 `gbPrgRom` + ROM 오프셋**(`뱅크*0x4000 + (CPU-0x4000)`).
   ⇒ 걸린 뒤 뱅크를 확인하려면 `read_memory(gameboyMemory, 0x4000, 16)` 을 읽어
     ROM 에서 그 16바이트가 어느 뱅크 머리와 같은지 찾으면 된다.
3. **호출과 호출 사이에도 에뮬은 돈다.** `press_buttons(frames=8)` 인데 프레임
   카운터가 **1,300** 올라간다. 프레임 단위 재현은 `pause` 로 얼린 뒤 `tap`.
   ⇒ **「프레임 정확」과 「BP」는 동시에 안 된다.** 필요한 쪽으로 갈아탄다.
4. `load_state`/`save_state` 는 **BP 로 멈춘 상태에서 거부된다**(`unsafe_halt`).
   `resume` → `pause` 로 한 번 정상화한 뒤 쓴다.

### 검산법 — BP 도구가 살아 있는지 먼저 확인할 것

`gbPrgRom` exec BP 를 **`0x000040`(VBlank 벡터)** 에 걸고 `run_frames(10)`.
여기서 안 걸리면 도구 문제이고, 걸리면 **정말로 그 코드가 안 도는 것**이다.
이 한 줄이 「뱅크 55 는 링크 전용」이라는 결론의 근거가 됐다(`docs/09` §0a-0m).

## ⛔ headless 로는 버튼이 안 먹는다 (2026-08-15 확정)

`launch(..., display=false)` (기본값)로 띄우면 **`press_buttons`/`set_input` 이
게임에 전혀 전달되지 않는다.** 프레임은 정상적으로 흐르고 `frame` 카운터도
올라가지만 화면이 1픽셀도 안 바뀐다(스크린샷 SHA-256 이 계속 같다).

    launch(content_path=..., system="gbc", display=True)   # ← 이래야 입력이 먹는다

이걸 모르고 한참을 헤맸다. 증상이 **"게임이 멈춘 것"과 구별되지 않는다** —
타이틀에서 A 를 60프레임 눌러도 그대로였고, 인게임 세이브스테이트에서도
그대로였다. 그래서 「오프닝 튜토리얼에선 메뉴가 안 열린다」는 오래된 메모도
사실은 이 문제였을 가능성이 크다.

**판별법**: 스크린샷을 두 번 찍어 `sha256` 이 같으면 입력이 아니라 표시 모드를
먼저 의심할 것.

## 세이브 붙이기 — SRAM 직접 주입

`검수자료/*.srm` 은 **카트리지 배터리 세이브**(SRAM 덤프)다. 세이브스테이트가
아니다. 이 게임은 `MBC5+RAM+BATTERY`, RAM 32 KB(4뱅크)라 파일도 정확히 32,768 B.

⚠ Mesen 어댑터는 실행할 때마다 포터블 디렉토리를 **통째로 갈아엎으므로**
`portable/Saves/*.srm` 에 미리 복사해 두는 방식은 매번 지워진다.
  ✅ **emucap 0.14.4 에서 고쳐졌다**(`e572c19 fix(mesen): preserve portable save
  data across launch`, 2026-08-20 확인). 0.14.4 이상을 쓰면 `Saves/` 에 넣어 두는
  방식도 된다. ⚠ 그래도 **아래 SRAM 직접 주입은 계속 유효**하고, 버전과 무관하게
  확실하다 — 어느 쪽이든 상관없다.
→ **실행 중인 에뮬의 SRAM 에 직접 쓴다.** `write_memory` 는 한 번에 16 KB 까지다.

```
pause
write_memory(memory_type="gbCartRam", address=0,     input_file={path:…, offset:0,     length:16384})
write_memory(memory_type="gbCartRam", address=16384, input_file={path:…, offset:16384, length:16384})
resume ; reset
```

`gbCartRam` 의 주소 0 이 `.srm` 의 오프셋 0 과 그대로 맞는다(끝 `0x7FC0` 까지
바이트 일치 확인). `reset` 은 SRAM 을 지우지 않는다.

### ⚠ 그런데 이 세이브로는 「이어하기」가 안 나온다

주입은 성공하는데(리셋 후 읽어도 값이 그대로) 타이틀에는 `NEW GAME` 만 뜬다.
**원본 JP ROM 에 같은 세이브를 넣어도 똑같다** — 즉 한글 패치와 무관하다.
게임의 세이브 유효성 판정을 아직 못 찾았다. 다음에 팔 곳:

- 부팅 직후 SRAM 을 읽는 코드에 read 브레이크포인트를 걸어 판정 분기를 본다
- 사용자 쪽 에뮬레이터에서 **세이브스테이트**(Mesen `.mss` 등)를 받으면 이 문제를
  통째로 우회할 수 있다 — `qa_screenshot/ingame_start.mss` 처럼

## ⛔ 검수용 세이브는 **파티원 이름이 영원히 일본어다** (2026-08-16 확정)

「セリーヌ」가 상태·스킬 화면에서 계속 일본어로 나오던 것은 **번역 누락이 아니다.**
이 게임은 파티원 이름을 **세이브에 저장한다**.
⛔ 예전에 여기 「개명 기능이 있으니 당연하다」고 적혀 있었는데 **틀렸다** —
  **이 게임에는 개명 기능이 없다**(사용자 확인 2026-08-20). 저장하는 이유는
  뉴게임 때 ROM 템플릿을 세이브로 복사하기 때문이다(아래 4번).
화면은 ROM 이 아니라 **RAM 을 읽는다.**

근거 사슬:

1. 화면에 뜬 4글자를 글리프 인덱스로 되짚으면 바이트 `d1 f8 b0 c1`(=「ディアス」)인데,
   빌드된 ROM 에서 그 바이트열은 **이벤트 대사에만** 남아 있다(UI 표는 전부 번역됨).
2. 그 바이트열은 **WRAM `0x0FD6`** 에 있다. 즉 화면은 RAM 을 그린다.
3. 검수용 `.sav` 안에 12명 이름이 **일본어로** 들어 있다
   (슬롯 3벌 — `0x0601`/`0x2601`/`0x4601`).
4. ROM 의 파티원 템플릿 표(뱅크 136 `0x220000`, 12 × 0x100 B)와 세이브 레코드가
   **1바이트 어긋난 채 완전히 같다**:
   `ROM+1`(인덱스 바이트) == `SRAM+0` 12/12 일치, `ROM+2` 이름 7 B == `SRAM+1` 12/12 바이트 동일.
   ⇒ **뉴게임 때 ROM 템플릿이 세이브로 복사된다.**

⇒ **이름 관련 QA 는 반드시 NEW GAME 으로 할 것.** 검수용 세이브로는 몇 번을
   번역해도 일본어가 나온다. 표 자체(`pcstat`)는 번역돼 있다.

⚠ 4번의 "뉴게임 때 복사된다"는 **구조 일치로 증명한 것**이고, 복사하는 코드를
  직접 짚지는 않았다. 확실히 하려면 뉴게임을 파티 편성 시점까지 진행해
  WRAM 을 덤프하거나, SRAM 쓰기에 브레이크포인트를 걸면 된다.

## ⚠ 메뉴 입력이 자주 씹힌다 — 한 번에 한 칸씩 확인할 것

`tap(press_frames=18~22)` → `run_frames(50)` 이 그나마 낫지만 그래도 씹히거나
두 칸 움직인다. **커서 위치는 화면 아래 도움말 줄로 확인한다**(「특기를 세트·
사용합니다」/「능력치를 확인합니다」…). 목표 항목에 닿을 때까지 한 칸씩 밟는다.

## 되는 경로: 세이브스테이트

`load_state("qa_screenshot/ingame_start.mss")` 는 **다른 wip 빌드에서 뜬 것이라도

## 화면의 깨진 한글 → 미번역 블록 찾기

미번역 일본어가 우리 한글 폰트로 그려지면 뜻 모를 한글이 된다. 그대로 되짚는다.

```bash
python scripts/unscramble.py --alloc assets/glyph_alloc.json \
    --rom "roms/Star Ocean - Blue Sphere (Japan).gbc" <화면에서 읽은 한글>
```

⚠ **스크린샷을 찍은 그 빌드의 `glyph_alloc.json`** 으로 되짚어야 한다.
⚠ 8×8 글자를 눈으로 읽는 것이라 **몇 글자는 틀리게 마련이다.** 복원된 조각
   중 **말이 되는 부분만 골라 ROM 전체 검색**하면 위치가 잡힌다.

### 실적 — 오프닝 「CHARACTER report」

화면: 「온갑도적대추쨘있녀습비감서적키」
→ unscramble: 「…は地…に移りすんでいる」(일부만 맞음)
→ `charmap.encode("に移りすんでいる")` 로 ROM 검색 → **뱅크 177 `0x2C617D`**
→ 주변을 훑어 **캐릭터 리포트(프로필) 블록 `0x2C4934~0x2C707C`, 약 5,858 B** 확정.

`docs/07` 의 지도에 없던 표다. **QA 한 번에 새 블록이 나왔다** — 지도가 아직
전수가 아니라는 증거이므로, 실기 QA 를 번역과 같은 우선순위로 돌릴 것.

## 부팅 구간을 잡는 법 — 진입점 스핀 ROM (2026-08-15 확립)

ENIX 로고처럼 **부팅 몇 초 안에 지나가는 화면**은 이 어댑터로는 그냥 못 잡는다.

- `reset` 은 **브레이크포인트를 전부 지운다**(`reconnected:true` = 어댑터 재접속).
- `launch` 가 돌아왔을 땐 이미 **프레임 300+** 이라 로고가 지나간 뒤다.
- `break_on_reset` 은 gb 에서 미지원.

⇒ **진입점에 무한 루프를 박은 디버그 ROM**을 만들어 세워 놓고 붙는다.

```python
d = bytearray(open("out/sobs_kr_wipNN.gbc","rb").read())
d[0x100], d[0x101] = 0x18, 0xFE          # JR -2  (원본은 00 C3 = NOP/JP)
open("out/_dbg.gbc","wb").write(bytes(d))
```

```
launch(_dbg.gbc, display=True)   # PC 가 0x0100 에서 멈춰 있다
pause
set_breakpoint(...)              # 원하는 만큼 건다
write_memory("gbPrgRom", 0x100, hex="00c3")   # 원복 -> 그대로 부팅이 시작된다
poll_events
```

`0x100` 은 헤더 체크섬 범위(`0x134~0x14C`) 밖이라 건드려도 부팅에 영향이 없다.
이 방법으로 ENIX 로고의 BG 타일 0 을 누가 쓰는지 **첫 시도에** 잡았다
(`0x000D83` 벌크 복사 → 뱅크 `0x88` `$644F`).

## 화면 글자를 눈으로 읽지 말 것 — `scripts/screen_text.py`

8×8 한글은 스크린샷으로 읽으면 반드시 틀린다. 실제로 「트윈소드」의 설명을
「롱소드」의 것으로 잘못 읽고 *표가 어긋났다*고 오진할 뻔했다.

```
emucap: dump_memory(path=DUMP)
python scripts/screen_text.py DUMP --rom out/sobs_kr_wipNN.gbc
```

타일맵 → 타일 비트맵 → 폰트 시트 대조 → 글리프 인덱스 → `glyph_alloc.json`
순으로 **화면에 실제로 그려진 글자**를 텍스트로 뱉는다. TSV 와 그대로 대조된다.

### ⚠ 비선택 메뉴 항목은 평면 하나만 찍는다 — 깨진 게 아니다

선택 안 된 항목의 타일은 평면0 이 전부 `FF` 이고 평면1 에만 글자가 있다
(`lo==hi` 인 폰트 바이트와 안 맞는다). 처음엔 "page3 글리프가 구 폰트 뱅크에
없어서 깨진 것"으로 오해했다. `screen_text.py` 가 평면1 을 되살려 다시 찾는다.
